# Ralph CLI ↔ Auto-Claude Integration Flow

This document explains how Ralph CLI integrates with Auto-Claude's spec system, kanban process, and task tracking.

---

## Overview: Shared Data Layer

Ralph CLI and Auto-Claude **share a common data layer** through the `.auto-claude/` directory structure. They read and write to the same files, enabling bidirectional integration.

```
project/
├── .auto-claude/
│   ├── specs/                    # Spec system (shared)
│   │   ├── 001-feature/
│   │   │   ├── spec.md           # Specification (Auto-Claude writes, Ralph reads)
│   │   │   ├── requirements.json # Requirements (Auto-Claude writes, Ralph reads)
│   │   │   ├── context.json      # Context (Auto-Claude writes, Ralph reads)
│   │   │   ├── implementation_plan.json  # Plan & subtasks (Auto-Claude writes/updates, Frontend reads for Kanban)
│   │   │   ├── cost_report.json  # Cost tracking (Auto-Claude writes, Ralph reads & aggregates)
│   │   │   ├── qa_report.md      # QA results (Auto-Claude writes, Ralph reads for success rate)
│   │   │   └── boundaries.json   # Permissions (Auto-Claude writes, Ralph reads)
│   │   └── 002-another/
│   │       └── ...
│   ├── worktrees/                # Stream management (Ralph manages, Auto-Claude uses)
│   │   └── tasks/
│   │       ├── 001-feature/      # Isolated workspace for spec 001
│   │       └── 002-another/      # Isolated workspace for spec 002
│   ├── budget.json               # Budget limits (Ralph writes/reads)
│   └── config.yaml               # Ralph configuration
└── .ralph-config.yaml            # Ralph CLI config (Ralph manages)
```

### 3. Ralph CLI Reads & Aggregates

Ralph CLI reads these files to provide analytics:

```bash
# ralph stats command:
# 1. Scans .auto-claude/specs/*
# 2. Loads all cost_report.json files
# 3. Loads all qa_report.md files
# 4. Aggregates data
```

**Code reference (`apps/backend/ralph_cli/commands/stats.py`):**

```python
def load_cost_reports(specs_dir: Path) -> list[dict]:
    """Load all cost reports from spec directories."""
    reports = []

    for spec_dir in specs_dir.iterdir():
        if not spec_dir.is_dir():
            continue

        cost_file = spec_dir / "cost_report.json"
        if cost_file.exists():
            data = json.load(open(cost_file))
            data["spec_name"] = spec_dir.name
            reports.append(data)

    return reports

def load_qa_reports(specs_dir: Path) -> list[dict]:
    """Load all QA reports from spec directories."""
    reports = []

    for spec_dir in specs_dir.iterdir():
        qa_file = spec_dir / "qa_report.md"
        if qa_file.exists():
            content = qa_file.read_text()
            passed = "APPROVED" in content or "✓" in content
            reports.append({
                "spec_name": spec_dir.name,
                "passed": passed,
            })

    return reports

def calculate_aggregate_stats(cost_reports, qa_reports) -> dict:
    """Calculate aggregate statistics."""
    total_cost = sum(r.get("total_cost_usd", 0) for r in cost_reports)
    total_sessions = sum(len(r.get("sessions", [])) for r in cost_reports)
    qa_passed = sum(1 for r in qa_reports if r.get("passed"))
    success_rate = (qa_passed / len(qa_reports) * 100) if qa_reports else 0

    return {
        "total_specs": len(cost_reports),
        "total_sessions": total_sessions,
        "total_cost_usd": total_cost,
        "avg_cost_per_spec": total_cost / len(cost_reports),
        "success_rate": success_rate,
        # ... more stats
    }
```

## Data Flow: Ralph CLI → Auto-Claude

### 1. Budget Management (Ralph → Files)

When Ralph sets a budget:

```bash
ralph budget set 50.00 --project /path/to/project

# Ralph writes to:
.auto-claude/budget.json
```

**`budget.json` structure:**
```json
{
  "global_budget_usd": 50.00,
  "total_spent_usd": 12.45,
  "remaining_usd": 37.55,
  "warning_threshold": 0.8,
  "spec_budgets": {
    "001-feature": 10.00,
    "002-another": 15.00
  },
  "last_updated": "2026-01-18T12:00:00Z"
}
```

**Auto-Claude reads this before builds:**
```python
# In run.py or agent.py:
def check_budget(project_dir, spec_name):
    budget_file = project_dir / ".auto-claude" / "budget.json"
    if budget_file.exists():
        budget = json.load(open(budget_file))

        # Check global budget
        if budget.get("global_budget_usd"):
            if budget["total_spent_usd"] >= budget["global_budget_usd"]:
                raise BudgetExceededError("Global budget exceeded")

        # Check spec-specific budget
        if spec_name in budget.get("spec_budgets", {}):
            spec_budget = budget["spec_budgets"][spec_name]
            spec_cost = get_spec_cost(spec_name)
            if spec_cost >= spec_budget:
                raise BudgetExceededError(f"Budget for {spec_name} exceeded")
```

## Data Flow: Frontend Kanban ↔ Spec System

### 1. Task List (Frontend reads `implementation_plan.json`)

The Kanban board displays tasks from the spec system:

```typescript
// In apps/frontend/src/renderer/stores/task-store.ts:

interface Task {
  id: string;
  specId: string;              // Maps to spec directory name
  status: TaskStatus;          // 'spec_creation' | 'planning' | 'coding' | 'qa_review' | 'complete'
  implementationPlan?: {
    phases: Array<{
      phase: string;
      subtasks: Subtask[];     // From implementation_plan.json
    }>;
    totalSubtasks: number;
    completedSubtasks: number;
  };
}

// Load task from spec:
async function loadTask(specId: string): Promise<Task> {
  const specDir = `.auto-claude/specs/${specId}`;

  // Read implementation plan
  const planPath = `${specDir}/implementation_plan.json`;
  const plan = await readJSON(planPath);

  // Read cost report
  const costPath = `${specDir}/cost_report.json`;
  const costReport = await readJSON(costPath);

  // Read QA report
  const qaPath = `${specDir}/qa_report.md`;
  const qaContent = await readText(qaPath);
  const status = qaContent.includes("APPROVED") ? "complete" : "qa_review";

  return {
    id: specId,
    specId: specId,
    status: status,
    implementationPlan: plan,
    costData: costReport,
    // ...
  };
}
```

### 2. Kanban Columns Map to Spec Status

```
┌─────────────────┬─────────────────┬─────────────────┬─────────────────┬─────────────────┐
│  Spec Creation  │    Planning     │     Coding      │   QA Review     │    Complete     │
├─────────────────┼─────────────────┼─────────────────┼─────────────────┼─────────────────┤
│ □ 001-feature   │ □ 002-api       │ □ 003-refactor  │ □ 004-bugfix    │ ✓ 005-docs      │
│   No plan yet   │   10 subtasks   │   5/12 done     │   QA: REJECTED  │   QA: APPROVED  │
│                 │   0/10 done     │   Cost: $2.45   │   Cost: $1.20   │   Cost: $0.50   │
└─────────────────┴─────────────────┴─────────────────┴─────────────────┴─────────────────┘
```

**Status determination:**
- `spec_creation`: No `implementation_plan.json` exists
- `planning`: Plan exists, no `cost_report.json`
- `coding`: Plan exists, cost report exists, not all subtasks complete
- `qa_review`: All subtasks complete, QA report exists but not APPROVED
- `complete`: QA report shows APPROVED

### 3. Subtask Progress (Frontend reads `implementation_plan.json`)

When you click a task card, the frontend shows subtasks:

```typescript
// In TaskSubtasks.tsx:
function renderSubtasks(plan: ImplementationPlan) {
  return plan.phases.map(phase => (
    <div key={phase.phase}>
      <h3>{phase.phase}</h3>
      {phase.subtasks.map(subtask => (
        <div key={subtask.id}>
          <Checkbox checked={subtask.status === 'completed'} />
          <span>{subtask.description}</span>
          <span>{subtask.files?.join(', ')}</span>
        </div>
      ))}
    </div>
  ));
}
```

**Auto-Claude updates subtask status during builds:**
```python
# In agents/coder.py:
def update_subtask_status(spec_dir, subtask_id, status):
    plan_file = spec_dir / "implementation_plan.json"
    plan = json.load(open(plan_file))

    # Find and update subtask
    for phase in plan["phases"]:
        for subtask in phase["subtasks"]:
            if subtask["id"] == subtask_id:
                subtask["status"] = status  # "pending" | "in_progress" | "completed"

    # Update counts
    completed = sum(1 for p in plan["phases"] for s in p["subtasks"] if s["status"] == "completed")
    plan["completedSubtasks"] = completed

    # Write back
    json.dump(plan, open(plan_file, "w"), indent=2)
```

## Example: Complete Workflow

### Scenario: User creates a spec, Ralph tracks it, builds succeed, Kanban updates

```bash
# 1. User creates spec via Auto-Claude frontend
# Frontend → Auto-Claude backend → Creates files:
.auto-claude/specs/001-login-feature/
├── spec.md
├── requirements.json
└── context.json

# 2. Auto-Claude planner creates implementation plan
# Planner agent → Writes:
.auto-claude/specs/001-login-feature/implementation_plan.json
{
  "phases": [
    {"phase": "planning", "subtasks": [...]},
    {"phase": "coding", "subtasks": [...]}
  ],
  "totalSubtasks": 12,
  "completedSubtasks": 0
}

# 3. Ralph CLI checks stats BEFORE build
ralph stats --project /path/to/project
# Output: Total specs: 1, Total cost: $0.00

# 4. Ralph CLI estimates cost BEFORE build
ralph estimate --spec 001-login-feature
# Output: Estimated cost: $3.50

# 5. User sets budget via Ralph
ralph budget set 10.00
# Ralph writes → .auto-claude/budget.json

# 6. Auto-Claude runs build
python run.py --spec 001-login-feature
# Auto-Claude creates worktree:
.auto-claude/worktrees/tasks/001-login-feature/
# Coder agent updates implementation_plan.json as it works:
# - Sets subtasks to "in_progress"
# - Sets subtasks to "completed"
# Coder agent writes cost_report.json:
.auto-claude/specs/001-login-feature/cost_report.json
{
  "total_cost_usd": 2.45,
  "sessions": [...]
}

# 7. Auto-Claude checks budget
# Reads budget.json → $2.45 < $10.00 → OK, continue

# 8. QA agent runs
# QA agent writes qa_report.md:
.auto-claude/specs/001-login-feature/qa_report.md
# Summary: APPROVED

# 9. Ralph CLI checks stats AFTER build
ralph stats --project /path/to/project
# Output:
# Total specs: 1
# Total cost: $2.45
# Success rate: 100% (1/1 passed)

# 10. Frontend Kanban updates
# Frontend reads:
# - implementation_plan.json → 12/12 subtasks completed
# - qa_report.md → Status: APPROVED
# - cost_report.json → Cost: $2.45
# Kanban moves task to "Complete" column

# 11. User reviews in UI
# Clicks task card → See all subtasks ✓
# Sees cost breakdown: Planner $0.50, Coder $1.50, QA $0.45

# 12. User merges via Ralph
ralph stream merge 001-login-feature --delete
# Ralph merges worktree → main branch
# Ralph deletes worktree
```

## Key Takeaways

1. **Shared File System = Integration**
   - Ralph CLI and Auto-Claude share `.auto-claude/` directory
   - No APIs needed - they read/write the same JSON/Markdown files

2. **Ralph CLI Aggregates, Auto-Claude Generates**
   - Auto-Claude creates individual spec files during builds
   - Ralph CLI aggregates across all specs for analytics

3. **Frontend Displays, Doesn't Modify**
   - Frontend reads spec files to show Kanban state
   - Frontend doesn't modify `implementation_plan.json` directly
   - Auto-Claude agents update plan during builds

4. **Budget Enforcement is Bidirectional**
   - Ralph CLI sets limits → `budget.json`
   - Auto-Claude checks limits before/during builds
   - Ralph CLI displays spending against limits

5. **Worktrees Enable Parallel Work**
   - Ralph manages isolated git worktrees
   - Each spec builds in its own worktree
   - No conflicts between parallel builds
   - User merges when ready

6. **Status Flows Through Files**
   - `implementation_plan.json` → Subtask completion
   - `qa_report.md` → Approval status
   - `cost_report.json` → Cost tracking
   - Frontend Kanban reflects these automatically
